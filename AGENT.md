# Ольга — студия маникюра

Telegram Mini App одного мастера из Благовещенска. Интерфейс — HTML, CSS и JavaScript без фреймворков. Сервер — Node.js и встроенный SQLite, без внешних зависимостей. Точка входа интерфейса: `tg-app/index.html`.

Название и город выбраны владельцем. Цены, график и описания придуманы для демонстрации. Изображения сгенерированы, не являются реальным портфолио Ольги. Контакт мастера намеренно не выдуман: до его заполнения кнопка связи объясняет, что это демо, и не пишет постороннему человеку.

## Запуск на компьютере

Нужен Node.js 24 или новее. Установка пакетов не требуется.

1. Открыть терминал в `C:\Users\Acer\Documents\tg-beauty-catalog\tg-app`.
2. Выполнить `node server.mjs`. На Windows также можно запустить `start.cmd`.
3. Открыть [приложение](http://127.0.0.1:4173/).

При запуске по умолчанию используется `APP_MODE=demo`. Записи сохраняются в `tg-app/.data/demo.sqlite`. Повторное открытие того же браузера восстанавливает клиента по техническому cookie; через 24 часа сессия истекает. В другом браузере создаётся отдельный демонстрационный клиент.

**Не открывать HTML двойным щелчком через `file:///`.** Для бронирования нужен HTTP-сервер и SQLite. Для остановки запущенного в терминале сервера — Ctrl+C.

## Просмотр на телефоне без бота

Для локальной проверки компьютер и телефон должны быть в одной доверенной сети Wi-Fi. Остановить прежний сервер и запустить из PowerShell:

```powershell
$env:HOST='0.0.0.0'
node server.mjs
```

На телефоне открыть `http://IP-КОМПЬЮТЕРА:4173/`, подставив локальный IPv4 компьютера. Если Windows блокирует входящие соединения, понадобится разрешение для Node.js в частной сети. Настройки брандмауэра приложение не меняет. `127.0.0.1` на телефоне обозначает сам телефон, а не компьютер.

В локальной демонстрации не вводить чувствительные сведения. Для внешней ссылки заказчику нужен отдельно выбранный HTTPS-хостинг; публичный адрес этим локальным запуском не создаётся.

## Что реализовано

### Сезонное оформление и эффекты

**Актуальное изменение:** лепестки удалены и заменены двумя короткими залпами светящихся искр (`celebration-spark`, `soft-firework`). Искры на активных элементах имеют оранжевый оттенок во всех сезонах. Обе автоматические прокрутки теперь длятся 450 мс. Упоминания лепестков ниже описывают предыдущий вариант; правила запуска, очистки и reduced-motion сохранены.

Сезон выбирается автоматически по времени Благовещенска (Asia/Yakutsk): весна — март–май, лето — июнь–август, осень — сентябрь–ноябрь, зима — декабрь–февраль. При возвращении в приложение и раз в минуту в открытом приложении проверяется смена сезона. Палитры находятся в конце `tg-app/styles.css`, селекторы `data-season` и `data-theme`. Фото каталога увеличены; навигация имеет полупрозрачный фон с непрозрачным запасным вариантом. Цвет кнопок и выбор светлой/тёмной темы по-прежнему берутся из Telegram; сезонные фоны и текст используют согласованную палитру приложения.

В `app.mjs` функции `seasonAt`, `sparkle` и `celebrateBooking` отвечают за сезон, искры при нажатии активных кнопок/полей и краткое падение лепестков на экране успешной записи. При ошибке или отмене записи лепестков нет; повторный показ того же подтверждения в одной сессии не запускает их заново. Декор не блокирует касания, удаляется после эффекта и отключается при `prefers-reduced-motion`. Новых внешних изображений, библиотек или видео нет. Тест границ сезонов: `node --test tests/season.test.mjs`.

В роли мастера пятая вкладка «Расписание» открывает общий календарь записей. У клиента остаются четыре вкладки. Сервер проверяет права мастера независимо от видимости кнопки. В демо роль переключается через «О мастере»; в production определяется по проверенному Telegram ID. Перенос отдельной записи не меняет другие визиты и не допускает пересечения с занятым временем.

- Каталог с категориями, ценами, длительностью и описанием состава.
- Портфолио с просмотром изображений и переходом к услуге.
- Календарь на 45 дней, свободные интервалы, автоматическое сохранение записи.
- Экран подтверждения, «Мои записи», история изменений.
- Перенос с сохранением прежнего времени при конфликте; отмена с подтверждением.
- Минимальный режим мастера: график, перерывы, блокировка времени, просмотр визитов, отмена и отметка завершения.
- Telegram SDK: тема, пользователь при серверной проверке, безопасные отступы и системная кнопка возврата. В обычном браузере — собственная кнопка возврата и переключатель темы.
- Переход в настоящий чат/карту только после заполнения контактов. Пока контакта нет, показано понятное объяснение.

В демо раздел «О мастере» → «Посмотреть режим мастера» временно переключает роль текущего демонстрационного клиента. Все действия остаются в тестовой базе. Это инструмент показа заказчику, а не вход в рабочую админку. Демонстрационный владелец видит все записи этой демобазы: не используйте её для реальных персональных данных.

## Навигация между экранами

Нижние вкладки: **Услуги · Работы · Мои записи · О мастере**.

| Экран в брифе | Имя маршрута в `app.mjs` | Переходы |
|---|---|---|
| Э1 — Услуги | `services` | Категория → фильтр; карточка → `service` |
| Э2 — Услуга | `service` | Фото → `photo`; выбрать время → `calendar`; вопрос → чат |
| Э3 — Работы | `works` | Фото → `photo` |
| Э4 — Просмотр работы | `photo` | Посмотреть услугу → `service` |
| Э5 — О мастере | `about` | Контакт, карта, сведения о данных; владелец → `admin` |
| Э6 — Выбор времени | `calendar` | День/слот → `checkout` |
| Э7 — Проверка записи | `checkout` | Сохранение → `success`; перенос → `booking` |
| Э8 — Подтверждение | `success` | Мои записи → `bookings` |
| Э9 — Мои записи | `bookings` | Визит → `booking`; переключатель истории |
| Э10 — Детали | `booking` | Перенос → `calendar`; отмена → диалог → обновлённый статус |
| М1 — Управление | `admin` | График, блокировки, визиты и их детали |

Функция `go()` открывает экран, `back()` возвращает к предыдущему с прежней прокруткой. Основные вкладки не накапливают историю. Внутренние маршруты не являются отдельными HTML-страницами. Открытие приложения заново начинает каталог; сохранённые визиты остаются в базе.

## Где менять данные

В `content.mjs`:

- `studio`: имя, город, описание, контакты, признак демонстрационного контента.
- `services`: `id`, категория, название, цена в рублях, длительность в минутах, состав, доплаты, номер изображения, `active`.
- `works`: подпись работы, `serviceId`, номер изображения.
- `rules`: горизонт календаря, минимальное время до визита, срок изменения, перерыв между клиентами и шаг сетки.
- `defaultSchedule`: исходные рабочие дни, часы и обед. Он используется только при создании базы. Уже действующий график меняется через экран мастера и сохраняется в SQLite.

`image` — квадрант фотолиста: 0 — нюд; 1 — френч; 2 — вишнёвое покрытие; 3 — педикюр. Для реального портфолио заменить фотолист или перевести `photo()` и CSS на отдельные файлы изображений.

После изменения `content.mjs` перезапустить сервер и обновить страницу. Постоянные ID услуг не переиспользовать для других процедур. Чтобы убрать услугу, поставить `active: false`. Будущие и прошлые записи сохраняют снимок названия, цены и длительности. Перенос скрытой услуги отклоняется с сообщением; вопрос решается с мастером.

Настройки времени демонстрации: Благовещенск, UTC+9 (`Asia/Yakutsk`), запись минимум за час, перенос/отмена минимум за два часа, интервал между клиентами 15 минут. Это демонстрационные правила, не согласованные условия реальной студии. При изменении `changeMinutes` скорректировать также текст ошибки в `database.mjs`, чтобы он соответствовал правилу.

## Сервер и целостность данных

Сервер использует `node:sqlite`. В базе: клиенты, сессии, расписание, брони, блокировки, события и результаты запросов.

Создание/перенос выполняются внутри `BEGIN IMMEDIATE`. Проверяется пересечение полного занятого интервала. Идемпотентный ключ не даёт повторному запросу создать вторую запись. Если ответ потерян, интерфейс запрашивает результат операции; при неясном результате предлагает повтор с тем же ключом.

Перенос сохраняет прежнюю бронь при конфликте. Отмена меняет статус и освобождает время, сохраняя историю. Прошедший визит не становится автоматически оказанной услугой: завершение отмечает мастер. Новый график или блокировка не вытесняют существующие брони.

Сервер выдаёт только явно перечисленные публичные файлы. База, токен, серверный код и тесты через HTTP не доступны. Cookie сессии имеет `HttpOnly`, `SameSite=Lax`; в рабочем режиме также `Secure`. Чужой идентификатор записи не даёт клиенту доступа к ней.

## Подключение рабочего Telegram Mini App

Рабочий запуск требует отдельной настройки: реальный контент, контакт мастера, бот, ID владельца, HTTPS-хостинг и база. Публикация в Telegram автоматически не выполнена.

1. Внести реальные сведения в `content.mjs`, установить `studio.demoContent=false` и `studio.telegramUsername`.
2. Передать `APP_MODE=production`, `BOT_TOKEN`, `OWNER_TELEGRAM_ID` в окружение сервера. Токен не помещать в браузерные файлы. При использовании `.env` запускать `node --env-file=.env server.mjs`.
3. Поставить сервер за HTTPS-прокси, сохраняющим исходный `Host`, и обеспечить постоянное хранение `.data/production.sqlite`. Демо использует другой файл `demo.sqlite`.
4. В настройках выбранного бота задать публичный HTTPS URL Mini App для кнопки запуска.
5. Открыть через Telegram и проверить реальный цикл на телефоне. SDK уже подключён: `https://telegram.org/js/telegram-web-app.js`.

Рабочий сервер откажется запускаться с демонстрационным контентом или без требуемых настроек. Сервер проверяет подпись `initData`, срок и ID; `initDataUnsafe` не используется для выдачи прав. Публичный каталог можно смотреть без входа, но личные записи требуют сессии. Переключения демонстрационной роли в рабочем режиме нет.

Основания реализации: [Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app), [SQLite в Node.js](https://nodejs.org/api/sqlite.html). Текст раздела «Обработка данных» перед реальным запуском нужно дополнить сведениями конкретного оператора и фактическими условиями хранения/удаления. Это не готовая юридическая политика.

## Проверки

Из `tg-app` выполнить:

```powershell
node --test tests/booking.test.mjs
```

Тесты работают с отдельными временными базами, не изменяют демонстрационные или реальные записи. Проверяют конкурентное бронирование, пересечение интервалов, повтор запроса, перенос с откатом при конфликте, отмену, историю, права, закрытость серверных файлов, происхождение запросов и восстановление после перезапуска. Отдельно проверяются подпись Telegram, срок сессии и назначение владельца.

На этапе сборки эти два тестовых сценария прошли. Через браузерные кнопки проверены создание, подтверждение, перенос, отмена и восстановление истории после перезагрузки; галерея → фотография → услуга; вход в демонстрационное управление, блокировка/открытие времени и сохранение графика. На ширине 320 px у каталога и календаря нет горизонтальной прокрутки, проверенные кнопки не меньше 44 px. Светлый интерфейс осмотрен на 390 px, тёмный — на 430 px. В демобазе оставлена одна отменённая запись «Проверка интерфейса» как след этой проверки.

Реальные Telegram Android/iOS, внешний HTTPS-хостинг и настоящий мастер в эту локальную проверку не входят. Проверка подписи Telegram в тестах использовала синтетические подписанные данные, не настоящий токен пользователя.

## Изображение

`assets/nails.png` создан встроенным ImageGen для этого проекта. Промпт: квадратный фотолист 2×2 без текста и рамок; сверху молочно-розовый нюд и френч, снизу вишнёвое покрытие и нюдовый педикюр; естественный свет, серый текстиль, реалистичная фактура кожи. ## Чего пока нет

Оплаты, реальной серверной рассылки напоминаний, полноценной CRM, нескольких мастеров, редактора контента, настоящего контакта, публичного HTTPS-адреса и подключённого рабочего бота. Автономное демо лишь имитирует уведомления внутри браузера и не означает публичный запуск. Не добавлять эти функции без отдельного запроса владельца.

## Автономная версия для портфолио

`tg-app/portfolio.html` открывает бесплатное автономное демо без Node.js, SQLite и Telegram-бота. Записи, подтверждения, напоминания, история клиента, календарь и кабинет мастера имитируются в браузере и сохраняются только в `localStorage` текущего посетителя. Сообщения никому реально не отправляются, а персональная ссылка подтверждения действует только в том браузере, где создана запись.

Для локального просмотра нужно раздавать папку `tg-app` любым статическим HTTP-сервером и открыть `/portfolio.html`; через `file:///` модульный JavaScript может блокироваться браузером. Для публикации достаточно бесплатного статического хостинга. Кнопка «Сбросить демонстрацию» удаляет только данные этого демо.
